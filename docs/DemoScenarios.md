# Demo сценарии

Перед запуском сценариев должен быть запущен сервер с включённым сидированием:

- MainDbContext
- AppIdentityDbContext

Примечание:
- все демо-данные уже подготовлены
- управление сидированием выполняется через `appsettings`
- см. ADR: [0018-seeding-infrastructure.md](./adr/0018-seeding-infrastructure.md)

---

## Роли

- студент — любой пользователь вида `*.student@example.com` (пароль по умолчанию: 1234qQ)
- ментор — любой пользователь вида `*.mentor@example.com` (пароль по умолчанию: 1234qQ)

Примеры:
- bob.student@example.com
- dave.mentor@example.com

------------------------------------------------------------------------

## 1. Student --- начало работы

Действия: Войти под пользователем student.demo@example.com\
Открыть курс «Основы C#»\
Перейти во вкладку Exercises\
Открыть любое упражнение\
Отправить первое сообщение в чат

Результат: - автоматически создаётся чат - статус упражнения =
OnStudent - упражнение появляется у ментора в Inbox

------------------------------------------------------------------------

## 2. Mentor --- проверка

Действия: Войти под пользователем mentor.demo@example.com\
Открыть Mentor Inbox\
Выбрать студента\
Открыть упражнение\
Прочитать сообщение студента\
Ответить в чат

Результат: - появляется диалог student ↔ mentor - статус упражнения =
OnMentor

------------------------------------------------------------------------

## 3. Mentor --- оценка (развилка)

Действия: Поставить оценку (mark)\
Нажать кнопку Accept

------------------------------------------------------------------------

### Вариант A --- mark = 0 (не принято)

Результат: - работа не принята - статус возвращается → OnStudent

Поведение: Студент дорабатывает решение\
Студент отправляет новое сообщение

Дальше: Сценарий повторяется (Student → Mentor → оценка)

------------------------------------------------------------------------

### Вариант B --- mark = 1 (принято, но можно улучшить)

Результат: - статус = Accepted - упражнение считается принятым

Поведение: Студент может начать заново\
Студент отправляет новое сообщение

Дальше: Статус → OnStudent\
Сценарий повторяется

------------------------------------------------------------------------

### Вариант C --- mark = 2 (финально принято)

Результат: - статус = Accepted - чат становится read-only - упражнение
помечается как завершённое в списке

Поведение: Никакие действия в чате невозможны

------------------------------------------------------------------------

## Что важно учитывать

Чат создаётся при первом сообщении\
Операционные данные не сидируются\
Статус отображается в списке упражнений\
Поведение определяется действиями пользователя

------------------------------------------------------------------------

## Why is that?

Сценарии показывают полный жизненный цикл упражнения\
Покрывают все ветки (0 / 1 / 2)\
Не используют искусственные демоданные\
Демонстрируют реальное поведение системы
