# Конфигурации DEV environments при разработке и тестировании 

📖 About this document
- Документ описывает возможные конфигурации среды разработчика и рекомендации по их использованию в проекте WorkshopCode (MVP).
- Вариант **4. Dev (тесты перед PR)** является обязательным требованием при подготовке и согласовании Pull Request.

## Варианты конфигураций

| Варианты конфигураций                                             | Для чего удобно использовать                                                                                                                                                                                       |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Dev (разработка бекенда)**                    | Разработка **только API** с/без подключением фронтенда. |
| **2. Dev (разработка фронтенда)**                  |  Разработка **React/Vite фронтенда**, API можно запускать локально или в контейнере вместе с БД|
| **3. Dev (тесты и отладка в процессе разработки)** | Проведение тестов в процессе разработки |
| **4. Dev (тесты перед PR)**                        | Проведение финальной сборки и тестов при подготовке и/или тестирование **Pull Request**|

## Dev (разработка бекенда)

| **Api**        | **Web**             | **Db** | **Data** |
| :------------- | :------------------ | :----- | :------- |
| VS (Debug/Run) | CLI (`npm run dev`) | Docker | Dev Seed |
| VS (Debug/Run) | 🔴 Отключен         | Docker | Dev Seed |

**Примечания:**  
1. При разработке бекненда не обязательно деражть активным Web.  

---

## Dev (разработка фронтенда)

| **Web**             | **Api + Db**                                            | **Data** |
| :------------------ | :------------------------------------------------------ | :------- |
| CLI (`npm run dev`) | {VS (Debug/Release) или CLI (dotnet) `Release`}  + DB (Docker) | Dev Seed |
| CLI (`npm run dev`) | Docker (api + db)                                       | Dev Seed |

**Примечания:**  
1. Можно использовать режим (Debug/Release) при запуске из Visual Studio.  
2. Режим ** Release** используется для контейнера и для CLI (dotnet) .  
3. Вариант с VS/CLI удобен для активной разработки; Docker (api+db) — для интеграционной проверки.  

---

## Dev (тесты и отладка в процессе разработки)

| **Api**                               | **Web**              | **Db** | **Data** |
| :------------------------------------ | :------------------- | :----- | :------- |
| Visual Studio (Debug/Release) + VS test       | CLI (`npm run test`) | Docker | Dev Seed |

**Примечания:**  
1. `npm run test` (dev) — юнит-тесты на исходных `.tsx/.js` без сборки, проверяют логику компонентов и функций.  
2. **VS** в Debug/Release — быстрая локальная проверка во время разработки.  

---

## Dev (тесты при подготовке и согласование PR)

| **Api**                                     | **Web**                                                | **Db** | **Data** |
| :------------------------------------------ | :----------------------------------------------------- | :----- | :------- |
| CLI (dotnet) `Release` | CLI (`npm run build && npm run test -- --watch=false`) | Docker | Dev Seed |

**Примечания:**  
1. `dotnet build` и `dotnet test` в Release — финальная проверка сборки API перед merge/PR.  
2. `npm run build` + `npm run test` — проверка React после сборки (аналог Release API).  
3. `npm run preview` не используется в DEV (только при подготовке релиза для main — ручная smoke-проверка собранного фронтенда).  

---
3. **Сборка в Release** (`--configuration Release`) рекомендуется и для контейнера, и для CLI — для единообразия поведения.  

## Итого для DEV

0. **ENVIRONMENT** 
   - всегда  `ASPNETCORE_ENVIRONMENT=Development`.

1. **DB**  
   - Запуск: всегда DB (Docker).  
   - Сидинг: `Dev Seed` при первом запуске.  

1. **API**  
   - Запуск: VS (Debug/Release)  или CLI (dotnet) или в контейнере.
   - При запуске CLI (dotnet) или в контейнере CLI (dotnet) режим ** Release** — для единообразия поведения с CLI.

2. **Frontend (React + Vite)**  
   - Запуск: `npm run dev` (порт 5173).  
   - Env: `.env.development` → `VITE_API_URL=http://localhost:5000`.  
   - CORS: API должен разрешать origin фронта.  

3. **Docker**  
   - Используется для `db` и опционально `api+db`.

4. **Порты и HTTPS** (для внешнего доступа)  
   - Host: localhost
   - API: 5000, Web: 5173, DB: 55432
   
5. **Единообразие**  
   - Node, npm, .NET SDK — фиксируются файлами настроек на уровне репо (наборы и версии пакетов, библиотек).
   - Секреты (пароли) — на уровне репо не фиксируются
