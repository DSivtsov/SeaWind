# ADR 0009: refactoring-clean-architecture
**Дата:** 2025-10-10

## Решение
Принята упрощённая архитектура **Clean без Domain**.  
Слои проекта:
- **API** — контроллеры, валидация, DTO.
- **Application** — бизнес-логика, сервисы, контракты.
- **Infrastructure** — EF Core, репозитории, доступ к данным.

Domain-проект исключён. Предметная логика временно сосредоточена в сервисах Application.

## Почему
- Для MVP — быстрее разработка и проще онбординг.  
- Меньше слоёв и шаблонного кода.  
- Достаточно для текущих сценариев WorkshopCode.  
- Позволяет позже эволюционировать в полный Clean/DDD без ломки структуры.

## Следствие
- Контроллеры остаются тонкими.  
- EF-модели и правила должны быть изолированы от бизнес-логики.  
- Возможен перенос в полноценный Domain при расширении проекта.
