# ADR-0030: Роли в JWT (JWT claims)

## Почему / Контекст

В рамках MVP проекта WorkshopCode требуется поддержка серверной авторизации по ролям для части API-роутов (Mentor/Admin), а также корректная работа стандартных механизмов ASP.NET Core:

- Сервер обрабатывает аутентификацию и общий запрет доступа, возвращая 401 и 403.
- До текущего решения запреты доступа не основывались на роли пользователя.
- Для поддержки role-based авторизации с использованием стандартных механизмов ASP.NET Core принято решение включать роль пользователя в JWT в виде role-claim.

Цель решения:
- обеспечить **O(1)** проверку роли на сервере;
- сохранить простую и детерминированную модель авторизации для MVP;
- не усложнять `/api/users/me` и фронтенд-контракты.

---

## Решение

### Общий принцип

Роль пользователя добавляется в JWT как `ClaimTypes.Role` **в момент логина**.

JWT становится источником серверной информации о роли пользователя **на время жизни токена**.

### Реализация

1. **Источник роли**
   - Роль берётся из ASP.NET Identity через `UserManager.GetRolesAsync(user)`.
   - В рамках MVP действует инвариант: **у пользователя ровно одна роль**.

2. **Формирование JWT**
   - `TokenService` добавляет claim:
     - `ClaimTypes.Role = <RoleName>`
   - Дополнительно включаются стандартные claims: `sub`, `email`, `iss`, `aud`, `exp`.

3. **Валидация JWT**
   - `AddJwtBearer` настроен на использование:
     - `RoleClaimType = ClaimTypes.Role`
   - Это позволяет использовать `[Authorize(Roles = "...")]` без обращения к БД.

4. **TTL токена**
   - В рамках MVP TTL JWT зафиксирован как **2 часа**.
   - Изменение роли в БД вступает в силу после перевхода пользователя или истечения токена.

---

## Следствия и правила применения

### Что разрешено
- Использовать `[Authorize(Roles = "Admin" | "Mentor" | ...)]` на API-роутах.
- Использовать `User.IsInRole(...)` в серверном коде.

### Что запрещено (MVP)
- Использовать role-based `[Authorize]` на эндпоинте `/api/users/me`.
  - `/api/users/me` всегда защищён **только `[Authorize]`**.
  - 403 из `/api/users/me` **никогда не возвращается**.

### Контракт `/api/users/me`
- Роль возвращается как **данные**, а не как решение доступа.
- `me.kind === "error"` — только реальная серверная ошибка, не auth/role.

---

## Out of Scope

- Refresh tokens.
- Отзыв JWT при смене роли.
- Claims transformation / динамическая подгрузка ролей на каждый запрос.
- Множественные роли пользователя.
