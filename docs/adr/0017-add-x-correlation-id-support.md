# ADR 0017: Поддержка X-Correlation-Id (сквозная трассировка запросов)
**Дата:** 2025-10-31  

## Почему
Нужен единый способ связать клиентский запрос с логами сервера и ответом API. Передача и возврат `X-Correlation-Id` позволяет быстро находить все записи, относящиеся к одному запросу, что упрощает диагностику ошибок и анализ производительности. Решение дополняет встроенные механизмы трассировки, предоставляя клиенту явный идентификатор запроса.

## Решение (как реализовано сейчас)
- **Имя заголовка.** Жёстко используется заголовок `X-Correlation-Id`.
- **Получение или генерация.** Если в запросе есть `X-Correlation-Id` и он непустой, используется его значение; иначе создаётся новый идентификатор (`GUID` в формате без дефисов, 32 символа).
- **Доступ в ходе обработки.** Значение помещается в `HttpContext.Items` под ключом `X-Correlation-Id`.
- **Трассировка в логах.** На время обработки запроса открывается лог‑scope, куда добавляется пара ключ‑значение с ключом `X-Correlation-Id`. Благодаря этому все логи в рамках обработки запроса содержат этот идентификатор.
- **Заголовок ответа.** В ответ всегда добавляется заголовок `X-Correlation-Id` с выбранным/сгенерированным значением.
- **Отсутствующие элементы.** В текущей реализации **нет** валидации формата значения, параметров конфигурации (переопределение имени заголовка, выключатель фичи) и добавления `correlationId` в `ProblemDetails`.

## Последствия
- Клиент может передать свой `X-Correlation-Id` и получит его же в ответе; при отсутствии — сервер сгенерирует новый и вернёт его.
- Все логи, сформированные в рамках запроса, будут содержать `X-Correlation-Id`, что упрощает поиск и корреляцию записей.
- Контроллеры/обработчики не требуют изменений; идентификатор доступен из `HttpContext.Items` и автоматически попадает в лог‑scope.
- Поведение согласовано между запросом, внутренней обработкой и ответом.

## Риски и ограничения
- Отсутствует валидация входного значения: потенциально возможно получение слишком длинных или нежелательных значений от клиента.
- Имя заголовка зафиксировано (`X-Correlation-Id`) и не настраивается через конфигурацию.
- Не выполняется добавление идентификатора в `ProblemDetails`.
- Формат создаваемого значения — `GUID` без дефисов (32 символа), что следует учитывать при сопоставлении с внешними системами.

## Примеры использования `X-Correlation-Id`
через `curl.exe` в PowerShell для `http://localhost:5000/api/me`:

**Вариант 1 — ручная передача**
```powershell
curl.exe -i -X GET "http://localhost:5000/api/me" `
  -H "accept: application/json" `
  -H "X-Correlation-Id: test-corr-123"
```
Ожидаемый ответ содержит:
```
X-Correlation-Id: test-corr-123
```

**Вариант 2 — автоматическая генерация**
```powershell
curl.exe -i -X GET "http://localhost:5000/api/me" `
  -H "accept: application/json"
```
Ожидаемый ответ содержит:
```
X-Correlation-Id: <уникальный_GUID_без_дефисов>
```

## Вне области ADR
- Интеграция со стандартом W3C Trace Context (`traceparent`, `tracestate`) и OpenTelemetry.
- Конфигурирование имени заголовка, включение/выключение фичи, добавление в `ProblemDetails` — рассматриваются как возможные будущие улучшения, но в текущую реализацию не входят.
