# ADR 0037: userId in `/api/auth/me`

Почему
------

Фронтенду необходим `userId` для корректной работы UI-логики:

1.  Формирование ключей кэша и локальных сто́ров
    (например: `chat:${userId}`).
2.  Связывание “моих” сущностей в интерфейсе.
3.  Реализация optimistic UI (помечать сообщение как “моё” до ответа сервера).
4.  Построение админских таблиц и ссылок.

При этом:

*   `userId` не должен передаваться в API как параметр авторизации.
*   Авторизация выполняется исключительно на основании подписанных JWT claims.

Существует два способа получения `userId` на фронте:

**A.** `GET /api/auth/me`
**B.** Декодирование JWT на фронте.

Декодирование JWT делает фронтенд зависимым от формата токена (`sub`, `nameidentifier`) и усложняет поддержку при изменении конфигурации Identity.

Для снижения связанности фронтенда с форматом JWT требуется единый стабильный контракт.

* * *

Решение
-------

1.  Используется endpoint:

```
GET /api/auth/me
```

2.  Сервер возвращает:

```json
{
  "userId": "...",
  "email": "...",
  "role": "Student"
}
```

3.  `AuthCtx.me` хранит минимальный набор:
    *   `userId`
*   `email`
*   `role`
    4.  Разделение ответственности:
    *   `me.userId` используется только для UI.
*   Проверка доступа — только через JWT claims.
*   Endpoint’ы “моих” ресурсов не принимают `/{userId}`.

Пример API:

```
GET  /api/support/chat/messages
POST /api/support/chat/messages
```

`userId` определяется сервером из токена.

* * *

Пример использования (Frontend)
-------------------------------

```ts
const authCtx = useAuthContext();

if (authCtx.me.kind === "ready") {
    console.log(`userId: ${authCtx.me.user.userId}`);
}
```

Типовая модель состояния:

```ts
type AuthMe =
  | { kind: "loading" }
  | { kind: "empty" }
  | { kind: "error" }
  | {
      kind: "ready";
      user: {
        userId: string;
        email: string;
        role: string;
      };
    };
```

Пример использования для ключа кэша:

```ts
const chatKey =
  authCtx.me.kind === "ready"
    ? `chat:${authCtx.me.user.userId}`
    : undefined;
```

* * *

Следствие
---------

*   Фронтенд не зависит от структуры JWT.
*   Контракт `/api/auth/me` остаётся стабильным.
*   Исключается риск подмены `userId`.
*   UI получает необходимый минимум данных без нарушения безопасности.

* * *

Out of Scope
------------

*   Поддержка нескольких ролей.
*   Расширенный профиль пользователя.
*   Refresh-токены и сложные auth-флоу.
