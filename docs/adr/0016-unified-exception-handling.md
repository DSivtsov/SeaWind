# ADR 0016: Единая обработка исключений (ProblemDetails)
**Date:** 2025-10-28

## Почему
В ASP.NET ошибки могут возникать на разных уровнях конвейера: в контроллерах, фильтрах, middleware аутентификации и при валидации модели. Это приводило к разнородным JSON-ответам и усложняло их обработку на клиенте. Использование только централизованного `CustomExceptionFilter` частично решало проблему, но не охватывало все источники ошибок.

Для обеспечения единообразия, удобства трассировки и предсказуемости клиентских ответов было принято решение перейти на единый формат ошибок на базе стандартного **ProblemDetails (RFC 7807)**, поддерживаемый ASP.NET Core.

## Решение
Все источники генерации ошибок приведены к единому механизму формирования ответов на основе `ProblemDetails`, который содержит:
- стандартные поля `type`, `title`, `status`, `detail`, `instance` (RFC 7807);
- дополнительное поле `traceId`, упрощающее трассировку конкретного запроса.

### Основные изменения:
- обновлён `CustomExceptionFilter` для возврата `ProblemDetails` вместо `ResponseDtoBase`;
- настроен `InvalidModelStateResponseFactory` для ошибок валидации моделей (`400`);
- доработаны `JwtBearerEvents (OnChallenge / OnForbidden)` для возврата `ProblemDetails` (`401 / 403`);
- добавлен `CustomizeProblemDetails` для автоматического добавления `traceId`;
- все контроллеры переведены на использование `ProblemDetails`;
- добавлен `SwaggerMapExceptionsType` для корректного отображения схем ошибок в Swagger.

Чтобы Swagger корректно отображал стандартные ошибки, в конфигурации используется метод `swgOpt.MapType<T>()`, который явно описывает структуру объектов ошибок:

## Следствие
- Единый формат ошибок по стандарту **RFC 7807** на всех уровнях приложения.
- Лёгкая трассировка запросов по `traceId` в логах.
- Упрощённая клиентская интеграция — фронтенд и автотесты получают предсказуемый JSON-ответ.
- Повышенная безопасность: в `Production` скрыт стек исключений, а в `Development` остаются диагностические данные.
- Расширяемость: добавление новых исключений не требует изменений в контроллерах.

## Out of Scope
- Логирование и корреляционные заголовки (`X-Correlation-Id`) вынесены в отдельный ADR.
