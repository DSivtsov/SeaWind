# ADR 0026: Подход к разработке страниц Frontend

## Почему / Контекст

В процессе разработки Frontend MVP возникла необходимость зафиксировать единый,
воспроизводимый и управляемый подход к разработке страниц и визуального слоя приложения.

Проект развивается итеративно, с высоким риском потери контекста (чаты, обсуждения, временные решения),
поэтому требовался формальный, но лёгкий архитектурный артефакт, который:
- фиксирует принятые договорённости,
- предотвращает преждевременное усложнение,
- позволяет продолжать работу без повторных пересогласований.

Дополнительно было осознанно проверено, существует ли реальная необходимость
разделения UX-режимов (public / private) на этапе MVP.
Разделение признано преждевременным при отсутствии объективного конфликта требований.

## Решение

Принят единый подход:

1. Введён **Base Theme v0** — общий базовый визуальный и UX-стиль приложения на этапе MVP.
2. Base Theme v0 применяется **ко всем страницам Frontend MVP** без разделения на UX-режимы.
3. Разделение UX-режимов (public / private) **НЕ применяется**, пока не возникнет реальный конфликт требований.
4. Любое будущее разделение допускается **только при наличии объективных критериев**:
   - конфликт плотности интерфейса;
   - конфликт поведения UI-паттернов;
   - конфликт ответственности экранов.

Таким образом, визуальный и структурный подход Frontend MVP:
- упрощён;
- единообразен;
- контролируем;
- не содержит преждевременных архитектурных допущений.

## Следствия / Правила применения

- Все новые страницы Frontend MVP реализуются в рамках Base Theme v0.
- Запрещено вводить альтернативные темы, UX-режимы или дизайн-ответвления без отдельного ADR.
- Layout-архитектура страниц подчиняется SiteMap проекта.
- CSS используется только для фона, layout и overlay-поверхностей.
- Компонентные стили реализуются через Mantine props.
- Любое усложнение визуального слоя требует отдельного обоснования и фиксации.

## Связанные документы

* **[Base Theme v0 — описание подхода](../frontend/base-theme-v0-approach.md)**
  Документ описывает **как именно применять Base Theme v0 на практике**:
  базовые UX-принципы, правила стилизации, ограничения по CSS, работу с layout и компонентами.

* **[SiteMap (MVP) — источник истины по экранам и маршрутам](../frontend/SiteMap.md)**
Единственный источник истины по:
  * списку экранов Frontend MVP,
  * маршрутам и route patterns,
  * ролям доступа и областям ответственности.
    Все Layout, Guards и Routing **обязаны соответствовать SiteMap**.
    Если экран или маршрут отсутствует в SiteMap — его **не существует в MVP**.

* **[Frontend guards — правила доступа](../frontend/WorkshopCode_Frontend_guard.md)**
  Описывает правила доступа по ролям и поведение guard’ов:
  какие маршруты доступны гостю, авторизованным пользователям и ролям,
  а также общее поведение при запрете доступа.

## Out of Scope

- Финальный дизайн продукта.
- Brand / marketing UI.
- Анимации, микро-интеракции.
- Будущие private-only UX-оптимизации (Mentor / Admin / Student).
