# ADR 0026: Подход к разработке страниц Frontend

## Почему / Контекст

В процессе разработки Frontend MVP возникла необходимость зафиксировать единый,
воспроизводимый и управляемый подход к разработке страниц и визуального слоя приложения.

Проект развивается итеративно, с высоким риском потери контекста (чаты, обсуждения, временные решения),
поэтому требовался формальный, но лёгкий архитектурный артефакт, который:
- фиксирует принятые договорённости,
- предотвращает преждевременное усложнение,
- позволяет продолжать работу без повторных пересогласований.

Дополнительно было осознанно проверено, существует ли реальная необходимость
разделения UX-режимов (public / private) на этапе MVP.
Разделение признано преждевременным при отсутствии объективного конфликта требований.

## Решение

Принят единый подход:

1. **Mantine default dark** используется как **базовая тема** Frontend MVP.
2. Компоненты Mantine применяются **из коробки**, без кастомизации, пока нет объективной причины.
3. Допускаются **локальные точечные overrides**, только если:
   - есть реальная UX-проблема;
   - есть браузерные ограничения (например, autofill);
   - Mantine default поведение не решает задачу.
4. Такие overrides должны быть:
   - локальными (component-scope);
   - осознанными;
   - минимальными;
   - документируемыми.
5. Разделение UX-режимов (public / private) **НЕ применяется** на этапе MVP.
6. Любое будущее разделение допускается **только при наличии объективных критериев**:
   - конфликт плотности интерфейса;
   - конфликт поведения UI-паттернов;
   - конфликт ответственности экранов.

Таким образом, визуальный и структурный подход Frontend MVP:
- основан на Mantine default dark;
- минимально кастомизируется;
- остаётся единообразным и контролируемым;
- не содержит преждевременных архитектурных допущений.

## Следствия / Правила применения

- Все новые страницы Frontend MVP реализуются на базе Mantine default dark.
- Запрещено вводить альтернативные темы или UX-режимы без отдельного ADR.
- CSS используется только при невозможности решить задачу средствами Mantine.
- Локальные CSS-хуки (например, `input-field`) допустимы только при наличии обоснования.
- Layout-архитектура страниц подчиняется SiteMap проекта.
- Любое усложнение визуального слоя требует отдельного обоснования и фиксации.

## Out of Scope

- Финальный дизайн продукта.
- Brand / marketing UI.
- Анимации и микро-интеракции.
- Будущие private-only UX-оптимизации (Mentor / Admin / Student).
