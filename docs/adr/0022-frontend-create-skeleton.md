## Path alias (@/)
В проекте используется alias @/ → src/ для импортов.
Цель: убрать глубокие относительные пути (../../..), упростить рефакторинг и повысить читаемость импортов.
Alias настроен на уровне TypeScript (tsconfig.app.json) и Vite (resolve.alias).
Решение принято в рамках MVP как минимальное и стандартное для Vite + React + TypeScript.

## VS Code project settings
В репозитории используется .vscode/settings.json с мягкими рекомендациями для VS Code.
Цель: единый стиль форматирования, автопочинка простых ESLint-ошибок и автоматическое обновление импортов при перемещении файлов.
Настройки применяются только в VS Code, не влияют на сборку и игнорируются другими IDE.

## ADR: Page + PageShell (Container / Presentational split)

### Context

Во фронтенде WorkshopCode требуется:

* единообразная обработка состояний экранов (`loading / empty / error / default`);
* минимизация дублирования UI-логики;
* безопасное масштабирование без усложнения App и роутинга;
* строгий MVP-scope без избыточных архитектурных слоёв.

### Decision

Принят паттерн **Page + PageShell** (известен как *Container / Presentational Components*).

Структура:

* **App** — отвечает только за роутинг.
* **Page (Container)** — логика экрана:

  * загрузка данных (`useEffect`);
  * управление состояниями (`useState`, union-типы);
  * обработка ошибок и retry.
* **PageShell (Presentational / UI Shell)** — переиспользуемый UI-каркас:

  * принимает `state`, `children`, опциональные UI-props;
  * не содержит бизнес-логики и сайд-эффектов;
  * отвечает только за отображение состояний экрана.

Пример цепочки вызовов:

```
App → Page → PageShell → Content
```

### Consequences

**Плюсы**

* Единый контракт экрана для всех страниц.
* Отсутствие дублирования loading/error/empty.
* Чёткое разделение ответственности.
* Простая типизация без `any`.
* Лёгкое расширение в рамках MVP.

**Ограничения**

* Дополнительный уровень компонента (осознанный и минимальный).
* PageShell не содержит логики загрузки данных.

### Scope

Применяется ко всем экранам WorkshopCode в рамках MVP
(Courses, Lectures, Exercises, Chats, WorkshopSessions).

### Notes

Паттерн выбран как **минимально достаточный**.
Более сложные архитектуры (FSD, Redux-layers, CQRS-frontend) сознательно **не используются** на этапе MVP.

## Semicolons (;)

В проекте используются обязательные точки с запятой (;) во всех файлах JavaScript / TypeScript. Это сознательное стилевое решение.

Причина — снижение риска edge-case’ов Automatic Semicolon Insertion (ASI) и единый, предсказуемый стиль кода для учебного и командного проекта.

Правило автоматически контролируется ESLint (semi: ["error", "always"]). Отсутствие ; считается ошибкой. JSX не затрагивается.
