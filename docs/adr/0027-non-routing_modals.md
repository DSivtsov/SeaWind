# ADR 0027: Non-routing модальные окна (Auth, Support и др.)

## Почему / Контекст

В рамках Frontend MVP требуется единый подход к реализации модальных окон, которые могут отображаться поверх любого экрана приложения и не зависят от текущего маршрута (URL). К таким окнам относятся Auth Modal (Registration / Login), Support Chat и аналогичные глобальные действия.

Routing-ориентированный подход (через URL) для таких сценариев избыточен и приводит к усложнению guards, навигации и UX. На практике пользователю важно выполнить действие (авторизация, обращение в поддержку) и вернуться к текущему контексту экрана без изменения маршрута.

В качестве опорного примера используется Auth Modal — Registration, уже согласованный и реализованный как non-routing modal.

## Решение

Зафиксировать следующий общий принцип для non-routing модальных окон:

- Non-routing modal:
  - не имеет собственного URL;
  - не участвует в routing и guards;
  - может открываться поверх любого экрана приложения.

- Размещение:
  - модальные окна рендерятся в подходящем Layout (например, `CoursesLayout`);
  - модалка логически принадлежит layout, а не конкретной странице.

- Управление состоянием:
  - одновременно может быть открыта **только одна** non-routing modal;
  - состояние открытия управляется локально в Layout (через state);
  - каждая модалка рендерится **сама**, без общего ModalHost.

- Поведение при смене маршрута:
  - модалка автоматически закрывается при смене route (поведение по умолчанию для MVP).

- Область применения:
  - Auth Modals (Registration / Login);
  - Support Chat modal;
  - другие глобальные сервисные модалки MVP.

## Следствия / Инструкция по применению

- Non-routing modal **не должна**:
  - изменять URL;
  - требовать отдельного route;
  - подключаться к RouteGuard.

- Для открытия модалки:
  - используется локальный state в Layout;
  - кнопки Header / Footer напрямую управляют этим state.

- Для закрытия модалки:
  - пользовательский action (Close / Cancel);
  - либо автоматическое закрытие при route change.

- Каждая модалка:
  - является самостоятельным React-компонентом;
  - не знает о routing;
  - получает `opened / onClose` через props.

- Auth Modal — Registration является **референсной реализацией** данного подхода.

## Out of Scope

- Стек модальных окон (несколько одновременно).
- Deep-linking в модалки через URL.
- Глобальный ModalHost / менеджер модалок.
- Сохранение состояния модалки между перезагрузками страницы.
