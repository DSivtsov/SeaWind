# ADR 0028: Vite Fast Refresh и Notifications

## Почему / Контекст

В Frontend MVP используется Vite с Fast Refresh и UI‑библиотека Mantine. Практика показала, что нарушение контрактов Fast Refresh (смешивание exports компонентов и утилит) приводит к нестабильному HMR. Аналогично, попытки «собрать свою» систему уведомлений поверх Mantine усложняют код без ценности для MVP.

Необходимо зафиксировать единые ограничения и правила, чтобы обеспечить стабильность разработки и предсказуемый UX.

## Решение

Зафиксировать следующие правила для Frontend MVP:

### Vite / Fast Refresh
- Файлы с React‑компонентами экспортируют **только компоненты** — `*.tsx файлы`.
- Утилиты, helpers, API‑функции выносятся **в отдельные файлы** — `*.tx файлы`.
- Запрещено смешивать компоненты и вспомогательные функции в одном модуле.

### Notifications (Mantine)
- Используется **`@mantine/notifications`**.
- `<Notifications />` подключается **один раз в корне приложения**.
- `Notification` — **UI‑примитив**, а не система уведомлений.
- Для MVP **не строится собственная система** уведомлений.
- Допускается тонкий helper поверх `notifications.show`.

Рекомендованный helper:
```ts
export function showSuccess(message: string, title?: string) {
  notifications.show({ message, title, color: 'green' });
}
```

## Следствия / Инструкция по применению

- Компонентные файлы проверяются на чистоту exports.
- Все toast/notifications вызываются через единый helper.
- Ошибка вида `Expected X arguments…` в первую очередь проверяется на **импорт неверной сигнатуры**.
- Любые отклонения требуют отдельного ADR.

## Out of Scope

- Кастомные менеджеры уведомлений.
- Многохостовые `<Notifications />`.
- Сложные очереди, persist, undo/redo для уведомлений.
- Автоматическая миграция существующих helpers вне MVP.
