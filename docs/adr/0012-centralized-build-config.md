# ADR 0012: Централизованное управление настройками сборки и пакетами

**Дата:** 2025-10-15  

## Решение  
Зафиксировать использование файлов `Directory.Build.props`, `Directory.Packages.props` и `global.json` для централизованного управления настройками сборки, версиями SDK и зависимостей NuGet во всех проектах репозитория.

## Почему 
Единая конфигурация гарантирует согласованное поведение сборки, тестов и CI/CD, предотвращает дрейф версий пакетов и SDK, и упрощает обновление зависимостей между проектами `src/*` и `tests/*`.

## Следствие  
* Все проекты автоматически наследуют настройки из `Directory.Build.props` (LangVersion, Nullable, TreatWarningsAsErrors и т.д.).
* Версии пакетов задаются централизованно через `Directory.Packages.props`; локальное указание `Version` в `.csproj` запрещено.
* Инструменты Visual Studio (NuGet Manager) и CLI (`dotnet add package`, `dotnet remove package`) корректно работают с централизованным управлением пакетами и обновляют зависимости как в проектных файлах (`.csproj`), так и в `Directory.Packages.props`. При ручной модификации файлов проекта и `Directory.Packages.props` необходимо следовать правилам.
* При ручном редактировании `.csproj` или `Directory.Packages.props` необходимо строго соблюдать правила централизованного управления версиями и зависимостями, зафиксированные в ADR.
* В корне репозитория добавляется `global.json` для фиксации версии .NET SDK, используемой при сборке и CI.
* При необходимости индивидуальных параметров проект может переопределить настройки через `Condition` или дополнительные `.props`/`.targets` файлы.
* Все скрипты `dotnet build/test` и CI должны использовать SDK, указанную в `global.json`, для соблюдения принципа **Single Source of Truth**.

## Примечание
Overrides допускаются только при объективной необходимости (платформенные ограничения, legacy-интеграции, бенч-регресс) и применяются **только для конкретного проекта**.
Каждый случай требует комментария в архитектурном описании и предварительного согласования.
